### Product Description
In the Industry 4.0 era, unplanned machinery downtime remains the highest cost driver for manufacturing plants. This project introduces an intelligent predictive maintenance system that processes real-time sensor streams to forecast asset failures and isolate their physical root causes via Explainable AI (XAI). 

The core innovation lies in bridging the gap between data science and operations: utilizing a multi-agent AI architecture (CrewAI), the system automatically translates complex model outputs into step-by-step, industry-standard, and fully actionable maintenance protocols to achieve a true zero-downtime vision.

### Product Features
* **Anomaly and Failure Prediction:** Forecasting the machine failure risk ahead of time using binary classification models.
* **Root Cause Analysis:** Concurrently calculating the probability distributions of 5 distinct failure types (TWF, HDF, PWF, OSF, RNF).
* **Data Augmentation (SMOTE):** Resolving the class imbalance caused by the scarcity of failure labels using intelligent data generation pipelines.
* **Explainable AI (XAI):** Utilizing the SHAP library to visually isolate and mathematically rank the top 3 anomaly-triggering sensor features.
* **Multi-Agent AI Architecture:** Deploying CrewAI to automatically translate complex statistical outputs into step-by-step, industry-standard maintenance protocols.
* **Dynamic Dashboard and Bulk CSV Upload:** Allowing operators to upload multi-row CSV data sheets to instantly render and track live sensor trends via Plotly graphs.

# Backlog Distribution Strategy

During Sprint 1, the product backlog was distributed among team members according to their areas of expertise. The primary objective was to enable parallel development, allowing team members to work independently without waiting for one another, thereby establishing the project's technical foundation efficiently.


Feyza (Product Owner & Data Scientist 1) was responsible for project management, GitHub repository organization, exploratory data analysis (EDA), feature engineering, and developing the initial machine learning model.

Özlem (Data Scientist 2) was responsible for handling class imbalance using SMOTE, designing the multi-class failure prediction model, and creating the SQLite database schema.

Nursenem (Scrum Master & AI Engineer 1) was responsible for setting up the backend infrastructure, configuring the FastAPI project, managing project dependencies, designing the API architecture, and developing a mock prediction service. Since the machine learning model was not yet available, the mock API enabled the frontend development to continue without delays.

Emre (AI Engineer 2 & Frontend Developer) was responsible for developing the user interface, implementing data input forms, and integrating the frontend with the mock API.



Sprint 1 followed a parallel development approach. While the data science team worked on data preprocessing and machine learning models, the backend team developed the API infrastructure, and the frontend team built the user interface using the mock API. This strategy minimized development bottlenecks, allowed simultaneous progress across all components, and established a solid foundation for integrating the real machine learning models and AI agents in Sprint 2.

# Backlog Distribution Strategy
Throughout Sprint 2, the product backlog was distributed among team members according to their areas of expertise. The primary objective was to integrate the machine learning models developed during Sprint 1 into the system, replace mock components with real implementations, and establish a fully functional end-to-end AI-powered predictive maintenance system. To achieve this, team members worked in parallel, ensuring a seamless integration process.

Feyza (Product Owner & Data Scientist 1) enhanced the machine learning model to satisfy the mandatory requirements specified in the project design document. Two new engineered features were introduced: Temperature_Diff, representing the difference between process temperature and air temperature, and Power, calculated by multiplying rotational speed and torque using a physical coefficient. Although the SMOTE oversampling technique was initially evaluated, it was ultimately discarded because it reduced the model's F1-Score on the test set and produced unstable results. Instead, LightGBM's built-in cost-sensitive learning mechanism (is_unbalance=True) was adopted to address class imbalance. A GridSearchCV optimization layer was integrated to determine the optimal hyperparameter configuration. Rather than using the probabilistic optimization approach provided by Optuna, GridSearchCV was preferred due to its deterministic, reproducible, and stable performance within the predefined parameter search space. Furthermore, instead of relying on the conventional 0.5 classification threshold, a dynamic threshold optimization procedure was implemented to maximize the F1-Score while improving recall and mitigating the effects of class imbalance. An additional interaction feature, Tool_Wear_Torque, was also incorporated to capture the relationship between tool wear, high torque, and structural resistance. These strategic improvements increased the model's F1-Score from 68% to 77% while maintaining a Precision of 89%. Finally, the optimized model was packaged as a single .pkl file using the optimal 0.80 decision threshold and delivered to Nursenem for API integration.

Özlem (Data Scientist 2) was responsible for finalizing the multiclass failure classification model. In addition, she developed an Explainable AI (XAI) module using the SHAP library to identify the three sensor values that contributed most significantly to each predicted failure. Finally, she delivered the trained model together with the SQLite database connection scripts to Nursenem for backend integration.

Nursenem (Scrum Master & AI Engineer 1) integrated the real .pkl model files developed by Feyza and Özlem into the FastAPI backend, replacing the mock prediction mechanism with actual machine learning models. In addition, Nursenem completed the CrewAI integration by developing two AI agents. The Data Analyst Agent analyzes sensor data to support the prediction process, while the Root Cause Maintenance Expert Agent evaluates both the SHAP explanations and the predicted failure type to generate maintenance recommendations and actionable plans for users.

Emre (AI Engineer 2 & Frontend Developer) integrated the frontend application with the real API developed by Nursenem, replacing the mock API used during Sprint 1. He also implemented interactive sensor data visualizations using Plotly, enabling users to monitor trends such as temperature increases and torque decreases through dynamic line charts generated from uploaded CSV files. Finally, he integrated the outputs of the AI agents into the user interface, presenting prediction explanations and maintenance recommendations in a clear, interpretable, and user-friendly manner.

Sprint 2 was carried out using an integration-focused parallel development approach. The data science, backend, and frontend teams worked simultaneously to successfully integrate the machine learning models, AI agents, and user interface into a unified system. By the end of the sprint, the application was fully operational from end to end. The objectives for Sprint 3 are to complete final system testing, perform performance optimizations, and prepare the application for deployment to the production environment.
